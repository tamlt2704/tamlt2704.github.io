---

## What Is LocalStack?

> "LocalStack is a **fake AWS** running in Docker. S3, SQS, DynamoDB, Lambda — all on your laptop. Same APIs. Same CLI. Zero cost."

```
Your app → AWS SDK → https://s3.amazonaws.com     (real AWS, costs money)
Your app → AWS SDK → http://localhost:4566         (LocalStack, free)
```

Same code. Different endpoint. That's the trick.

---

## Start LocalStack

```bash
docker run -d --name localstack \
  -p 4566:4566 \
  -e SERVICES=s3,sqs,dynamodb,lambda,apigateway,secretsmanager \
  localstack/localstack
```

One container. All the AWS services you need.

Install the LocalStack CLI wrapper (optional but convenient):

```bash
pip install awscli-local
```

Now `awslocal` = `aws --endpoint-url=http://localhost:4566`. Less typing.

## What Is S3?

Tomás explains:

> "S3 is a **filing cabinet with infinite drawers**. You create a **bucket** (a drawer), then put **objects** (files) in it. Each object has a **key** (the file path) and a **body** (the file content)."

```
S3
└── Bucket: launchpad-uploads
    ├── profiles/user-1.jpg      ← object
    ├── profiles/user-2.jpg      ← object
    └── reports/march-2024.pdf   ← object
```

No folders. The `/` in the key is just a convention. S3 is flat — every object is identified by bucket + key.

| Concept | Analogy | What It Is |
|---|---|---|
| **Bucket** | A drawer | Top-level container, globally unique name |
| **Object** | A file in the drawer | The actual data + metadata |
| **Key** | The label on the file | The "path" to the object |

## Create a Bucket

```bash
awslocal s3 mb s3://launchpad-uploads
```

That's it. Bucket created.

```bash
awslocal s3 ls
```

```
2024-01-15 10:00:00 launchpad-uploads
```

## Upload a File

```bash
echo "hello from localstack" > test.txt
awslocal s3 cp test.txt s3://launchpad-uploads/docs/test.txt
```

List it:

```bash
awslocal s3 ls s3://launchpad-uploads/docs/
```

```
2024-01-15 10:01:00         22 test.txt
```

Download it:

```bash
awslocal s3 cp s3://launchpad-uploads/docs/test.txt downloaded.txt
cat downloaded.txt
```

```
hello from localstack
```

Same file. Round-tripped through fake S3.

## From Your Java App

The AWS SDK doesn't know it's talking to LocalStack. You just override the endpoint:

```yaml
# application.yml
aws:
  s3:
    endpoint: http://localhost:4566
    region: us-east-1
    bucket: launchpad-uploads
```

```java
S3Client s3 = S3Client.builder()
    .endpointOverride(URI.create("http://localhost:4566"))
    .region(Region.US_EAST_1)
    .build();

// Upload
s3.putObject(
    PutObjectRequest.builder()
        .bucket("launchpad-uploads")
        .key("profiles/user-1.jpg")
        .build(),
    Path.of("/tmp/photo.jpg"));

// Download
s3.getObject(
    GetObjectRequest.builder()
        .bucket("launchpad-uploads")
        .key("profiles/user-1.jpg")
        .build(),
    Path.of("/tmp/downloaded.jpg"));
```

When you move to real AWS, you remove the `endpointOverride` line. Everything else stays the same.

## Presigned URLs

Ava asks:

> "I don't want the backend to proxy every file download. Can the browser download directly from S3?"

Yes. **Presigned URLs** — a temporary, signed URL that gives anyone access to one specific object for a limited time.

```bash
awslocal s3 presign s3://launchpad-uploads/docs/test.txt --expires-in 3600
```

```
http://localhost:4566/launchpad-uploads/docs/test.txt?X-Amz-Algorithm=...&X-Amz-Expires=3600&...
```

Anyone with that URL can download the file. For one hour. No credentials needed.
