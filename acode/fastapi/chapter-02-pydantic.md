## The Problem

Marcus: "The old Flask API returns `created_at` as a string sometimes and a timestamp other times. Sometimes `user_id` is an int, sometimes a string. I'm writing `if (data.user_id)` checks everywhere. Give me a contract."

Pydantic models ARE the contract. They define exactly what goes in and what comes out. If the data doesn't match, the request fails with a clear error — before your code even runs.

---

## Request Models (What Goes In)

```python
# app/schemas/project.py
from pydantic import BaseModel, Field
from datetime import datetime


class ProjectCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    description: str | None = Field(default=None, max_length=500)
    color: str = Field(default="#6366f1", pattern=r"^#[0-9a-fA-F]{6}$")


class ProjectUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=1, max_length=100)
    description: str | None = None
    color: str | None = Field(default=None, pattern=r"^#[0-9a-fA-F]{6}$")
```

### What Pydantic Validates

| Field | Constraint | Invalid Input → Error |
|---|---|---|
| `name: str` | Required, must be string | `null` → "Field required" |
| `min_length=1` | Can't be empty | `""` → "String should have at least 1 character" |
| `max_length=100` | Can't be too long | 101 chars → "String should have at most 100 characters" |
| `pattern=r"^#..."` | Must match regex | `"red"` → "String should match pattern" |
| `str \| None = None` | Optional, nullable | omitted → `None` (no error) |

All of this is validated BEFORE your route function runs. If validation fails, FastAPI returns a 422 with detailed errors. Your code never sees bad data.

## Response Models (What Comes Out)

```python
# app/schemas/project.py
class ProjectResponse(BaseModel):
    id: int
    name: str
    description: str | None
    color: str
    created_at: datetime
    owner_id: int

    model_config = {"from_attributes": True}
```

Use it in the route:

```python
@app.post("/projects", response_model=ProjectResponse, status_code=201)
def create_project(project: ProjectCreate):
    # ... create in database ...
    return db_project  # SQLAlchemy model → Pydantic serializes it
```

### What `response_model` Does

1. **Filters fields** — only fields in `ProjectResponse` are returned (hides internal fields like `password_hash`)
2. **Serializes** — converts datetime to ISO string, enums to values
3. **Documents** — the OpenAPI schema shows exactly what the response looks like
4. **Validates output** — if your code returns wrong types, you get an error (catches bugs)

## Separating Create, Update, and Response

```python
# The pattern: one model per operation
class ProjectCreate(BaseModel):    # POST body — required fields
    name: str
    description: str | None = None

class ProjectUpdate(BaseModel):    # PUT/PATCH body — all optional
    name: str | None = None
    description: str | None = None

class ProjectResponse(BaseModel):  # GET response — includes DB fields
    id: int
    name: str
    description: str | None
    created_at: datetime
    owner_id: int
```

Why three models? Because:
- Creating requires `name` (mandatory)
- Updating makes everything optional (only send what changed)
- Response includes `id`, `created_at`, `owner_id` (generated by the DB, not sent by the client)

## Nested Models

```python
class UserBrief(BaseModel):
    id: int
    name: str
    avatar_url: str | None

    model_config = {"from_attributes": True}


class TaskResponse(BaseModel):
    id: int
    title: str
    status: str
    assignee: UserBrief | None  # nested object
    project_id: int
    created_at: datetime

    model_config = {"from_attributes": True}


class ProjectDetailResponse(BaseModel):
    id: int
    name: str
    description: str | None
    tasks: list[TaskResponse]  # list of nested objects
    member_count: int
    created_at: datetime

    model_config = {"from_attributes": True}
```

## Validation Examples

```python
from pydantic import BaseModel, Field, field_validator, EmailStr
from enum import Enum


class TaskStatus(str, Enum):
    todo = "todo"
    in_progress = "in_progress"
    done = "done"
    cancelled = "cancelled"


class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200)
    description: str | None = None
    status: TaskStatus = TaskStatus.todo
    priority: int = Field(default=3, ge=1, le=5)  # 1-5
    assignee_id: int | None = None

    @field_validator("title")
    @classmethod
    def title_not_empty(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("Title cannot be only whitespace")
        return v.strip()


class UserCreate(BaseModel):
    email: EmailStr  # validates email format
    name: str = Field(min_length=2, max_length=50)
    password: str = Field(min_length=8)

    @field_validator("password")
    @classmethod
    def password_strength(cls, v: str) -> str:
        if not any(c.isupper() for c in v):
            raise ValueError("Password must contain an uppercase letter")
        if not any(c.isdigit() for c in v):
            raise ValueError("Password must contain a digit")
        return v
```

```bash
curl -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "   ", "priority": 10}'
```

```json
{
  "detail": [
    {"loc": ["body", "title"], "msg": "Title cannot be only whitespace"},
    {"loc": ["body", "priority"], "msg": "Input should be less than or equal to 5"}
  ]
}
```

Two errors caught. Clear messages. Exact field locations. Marcus can show these directly in the UI.

## model_config: Connecting to SQLAlchemy

```python
class ProjectResponse(BaseModel):
    id: int
    name: str
    created_at: datetime

    model_config = {"from_attributes": True}
```

`from_attributes = True` tells Pydantic to read from object attributes (like SQLAlchemy models) instead of requiring a dict. Without it:

```python
# ❌ Fails: SQLAlchemy model is not a dict
return db_project

# ✅ Works with from_attributes = True
return db_project  # Pydantic reads db_project.id, db_project.name, etc.
```

## Quick Reference

```
────────────────────────────────┬──────────────────────────────────────
Feature                         │ Syntax
────────────────────────────────┼──────────────────────────────────────
Required field                  │ name: str
Optional field                  │ name: str | None = None
Default value                   │ color: str = "#6366f1"
Min/max length                  │ Field(min_length=1, max_length=100)
Number range                    │ Field(ge=1, le=5)
Regex pattern                   │ Field(pattern=r"^#[0-9a-f]{6}$")
Email validation                │ EmailStr (from pydantic)
Enum constraint                 │ status: TaskStatus
Custom validator                │ @field_validator("field")
Nested model                    │ assignee: UserBrief | None
List of models                  │ tasks: list[TaskResponse]
Read from ORM objects           │ model_config = {"from_attributes": True}
response_model=X                │ Filter & document the response
────────────────────────────────┴──────────────────────────────────────
```
